Foreign keys from attributes. Given a schema with attributes only, such as an import gives, and declarations f : A -> B where a1 = b1 ... an = bn, a query from that schema to the same schema with the foreign keys added. A row of A is joined with the rows of B whose columns b1 ... bn equal its columns a1 ... an, and with the rows those reach in turn, so the declared foreign keys may not form a cycle. The columns on the right should be a key of B: a row with no match is left out, and a row with two matches gives two rows. To check the keys first, state them as constraints and check them; to rename tables and columns after, use delta along a mapping into the schema of the result (schemaOf). Up to the columns it keeps, this is Pi along the mapping that sends each column on the left to the path through its foreign key to the column on the right (David Spivak's construction).
